# 商业化战略一页纸：resume-lint

> 由 `/open-core-strategy` 产出 · 2026-09-14

## 模式选型

**open-core（规则引擎开源 + 托管免费查 + 详细报告付费）**

决策路径（走 skill 第 1 步决策树）：
- 产品形态 = 工具站（可完全静态化）→ 不需要托管云模式
- 目标受众含开发者 → 引流价值高，引擎开源能换 star/信任/贡献者
- 付费点 = 「省心深度」：把 8 条规则的免费清单升级为逐条改写建议 + 模板

| 免费侧（永远） | 付费侧（¥9.9 买断） |
|---|---|
| 全部基础规则检查（8 条） | 逐条**改写示例**（不只是指出问题） |
| 总分 + 问题清单 | 针对 JD 的关键词差距报告 |
| 浏览器本地处理、无上传 | 行业化模板包（校招/社招/外企） |
| CLI（开源） | 优先支持 |

## License 选择

**MIT**。理由：目标是最大化传播与信任（隐私叙事），暂不做双授权
（无企业嵌入场景）；付费价值在「内容与服务」不在「代码闭源」。
贡献者少，暂不需要 CLA；出现稳定外部贡献者时再补。

## 漏斗衔接

```
GitHub star（引擎开源，dev 受众）
   → 托管页免费体检（任何人）
      → ¥9.9 详细报告（求职刚需人群）
         → 模板包/批量（HR 或求职机构，未来）
```

## 支付渠道（`/payments-setup` 决策树结论）

- 买家：中文求职者为主，少量海外 → **国内优先**
- 个人无主体 → 首选 **¥9.9 虎皮椒/聚合**（个人可用、费率 ~1%）；海外用户走
  **Polar/LemonSqueezy $1.99** 双轨
- 均为**一次性买断**，回避国内个人做周期扣款的政策难度
- 集成属于后续任务（见 HANDOFF.md 下一步）

## 红线

- 核心基础检查永不收费（它是引流与信任的根基）
- 「本地处理」承诺写进一切文案——代码开源就是证明
- 简历内容永不入库（连日志都不记原文）

## 当前阶段

纯开源积累期（引擎+免费托管页先行），付费报告在免费版有真实留存后再上（预计发布后 2-4 周）。
