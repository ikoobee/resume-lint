## 电鸭社区帖（首选）

> 节点：创作者/作品分享。社区是远程工作者与自由职业者——简历是他们的刚需。
> 语气：平实分享，像在群里跟朋友说话。

**标题**：做了个开源的简历体检工具，简历不用传到任何服务器

**正文**：

大家好，我做了个小工具 resume-lint，起因是自己（和身边找工作朋友）的老问题：
简历投出去石沉大海，不知道问题出在简历还是岗位。想用线上工具查一下，发现每个都要先把简历传上去——手机号、全部经历都在别人的服务器上。

这个工具反着来：**所有检查都在浏览器本地跑，断网也能用，代码开源可审计**。

- 8 条规则：量化密度（经历里有没有数字）、责任词占比（「负责」太多像岗位说明书）、套话黑名单（吃苦耐劳/精通连用）、敏感信息（身份证号千万别写简历上）、板块完整性等
- 每条问题带「怎么改」的建议
- 免费，无注册，无 Cookie

局限也坦白：目前只支持粘贴文本（.txt/.md 可拖入），PDF 在路上；规则阈值按中文社招简历调的，可能有不准的地方，欢迎拿自己的简历试一下拍砖。

在线用：https://resume-lint.ikoobee.com
源码：https://github.com/ikoobee/resume-lint

特别想听正在找工作/刚改完简历的朋友说说：还希望它查什么？

## 掘金技术文

> 标题走技术向（掘金文化：讲实现不讲产品）。发布后同稿可同步 SegmentFault/知乎专栏。

**标题（候选其一）**：
1. 纯前端实现「简历体检」：8 条规则的正则与启发式设计
2. 零依赖做一款浏览器本地工具：resume-lint 的架构取舍

**大纲**：

1. 背景（2 段）：为什么不传服务器（隐私叙事）+ 为什么不用 AI（简历发给模型=上传的另一种形式）
2. 架构：零依赖静态站的取舍——`node --test` 内置测试器、无构建、CF Pages 免费层
3. 规则设计（正文主体，每条一小节，给核心代码）：
   - 量化密度：行级正则 + 占比阈值
   - 责任词 vs 成果动词：词频对比的启发式
   - 敏感信息：身份证/出生日期的正则与误报控制
   - 阈值校准的教训（600→500：一页精简简历的误报代价）
4. 每条规则 = 纯函数 `(text) => issues[]`：可测试性带来的好处（19 个单测）
5. 结尾一段带产品：开源地址 + 在线地址 + 「欢迎 PR 加规则」

## 知乎答题

> 不发文章，答高频问题。选「简历」「简历优化」「求职」话题下浏览量高且半年内仍活跃的问题。

**目标问题类型**（搜索关键词）：
- 「简历上哪些内容是 HR 眼中的减分项？」
- 「简历怎么写才能通过初筛？」
- 「没有量化数据的工作经历怎么写简历？」

**答题模板**（真诚作答为主体，工具是补充）：

```
先给干货（500-800 字，可从 8 条规则展开成自查清单，
比如：删身份证号、每条经历带数字、砍掉「吃苦耐劳」）……

最后一段自然带出：
「这些检查我整理成了一个免费工具，浏览器本地跑、简历不用上传，
自查一遍 3 分钟：https://resume-lint.ikoobee.com」
```

纪律：**先答后荐**，干货占比 >80%；同一问题下已有高质量答案的就不凑热闹。
